Privacy Policy

Your screenshots stay on your device, unless you send them to your own Drive.

What Full Page Capture stores, when it reads a page, and exactly what happens when you choose to send a capture to Google Drive.

Full Page Capture takes screenshots and screen recordings of the page you're viewing, lets you annotate them, and exports the result as PNG, JPG, PDF, or video. Every one of those steps runs inside your browser. The extension has no server of its own, and the only outside service it will ever talk to is Google Drive — and only once you explicitly ask it to.

01What gets captured, and when

A capture — full page, visible area, a selected region, a hovered element, a scrolling panel, or a screen recording — only starts when you trigger it yourself: a toolbar click, a keyboard shortcut, or a right-click menu item. The extension does not watch, read, or capture anything in the background.

Capturing a page necessarily means reading its visible content so it can be turned into an image or video — that's what the activeTab and scripting permissions are for. That content is processed entirely in memory inside your browser to build the capture; it is not sent anywhere as part of this step.

02Where a finished capture lives

  • While you're editing it — the image or recording is held in the extension's own tab (the editor), and in your browser's local, per-origin storage (including the Origin Private File System used to write a recording to disk chunk-by-chunk, so a crash doesn't lose the whole thing).
  • "Recent" captures — if you turn this on in Settings, finished captures are kept in your browser's local storage so you can reopen them later. This is local-only and off by default; turning it off clears what's there.
  • Exporting — clicking Download, Copy, or Save hands the file to Chrome's/Edge's own downloads API (saved to your normal downloads folder) or your system clipboard. Nothing about that file passes through us.
  • Settings (output format, shortcuts, defaults) are saved with chrome.storage.sync — the browser's own built-in setting sync tied to your browser profile, not a service we run or can see.

None of the above ever leaves your device unless you take the separate, explicit action described in section 03.

03Sending a capture to Google Drive (optional)

"Send to Drive" is the one feature that reaches outside your browser, and only runs when you click it.

  • Sign-in — the extension uses Chrome's/Edge's built-in identity API to get a Google sign-in token. You see Google's own consent screen; the extension never sees your Google password.
  • Why the broad Drive scope — the permission Google shows is the full drive scope rather than the narrower "files this app created" scope. That's because this feature lets you pick an existing folder in your Drive to upload into, and the narrow scope can't see or write into a folder it didn't create itself. The extension still only uploads the one capture file you asked to send — it does not list, read, or modify anything else in your Drive — but the permission screen can't express that distinction, so the broader grant is what Google shows.
  • What's uploaded — exactly the capture you were working on (the image or video file), uploaded directly from your browser to googleapis.com (Google's own servers) into your own Google account. It never passes through a server belonging to us, because we don't have one.
  • The sign-in token — kept by the browser's identity API for this purpose; the extension does not copy it elsewhere.

04Where it doesn't go

Verifiable

Search the extension's source and the only network calls you'll find are to googleapis.com / accounts.google.com for the Drive feature in section 03, and (outside the version submitted to this store listing) a version check against this project's own public GitHub repository. There is no analytics call, no ad network, no crash-reporting service, and no server of ours anywhere in the code — because none exists for it to call.

05Permissions, and why each one exists

PermissionWhat it's for
activeTab / scripting Reading the current page's content and layout so it can be turned into a screenshot, and running the on-page tools (area select, element hover, the annotation overlay) when you invoke them.
downloads Saving an exported PNG, JPG, PDF, or recording to your normal downloads folder when you click Download.
storage Saving your settings (chrome.storage.sync) and, if you enable it, your "Recent" captures list (local only), as described in section 02.
identity Getting a Google sign-in token for "Send to Drive" — see section 03. Not used anywhere else.
notifications Showing a system notification when a long capture, recording, or Drive upload finishes, in case you've switched to another tab or window.
host access
googleapis.com		 Talking directly to Google's Drive API for section 03's upload. No other host is contacted.

06Changes to this policy

If this ever changes, the date at the top of the page changes with it. The extension's source is public, so any change in behavior can be checked directly against the code rather than taken on faith.
